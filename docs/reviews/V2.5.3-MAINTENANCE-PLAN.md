### OCR-252-005 - small-group suppression

**Status:** implemented on `main`; v2.5.3 retest pending.

The analytics design documents require a minimum cohort size and suppression of
small groups. The active course overview currently returns enrolment, completion,
pulse, reaction, and skill-tree aggregates without a suppression signal or
minimum-cell check. An instructor or administrator viewing a very small course
could infer an individual learner's activity from the aggregate.

Implemented controls:

- `analytics_min_cohort_size` platform setting, default **5**, editable in
  **Admin → Settings → Security**. Set to `0` only in a trusted test environment.
- Three explicit states: **available**, **suppressed**, and **no_evidence**.
- Course overview suppresses activity metrics and skill-tree data for cohorts
  between 1 and the minimum; zero-activity cohorts show `no_evidence` with null
  metrics rather than measured zeroes.
- The exercise table applies the same check per exercise cohort.
- Pulse-comment access is suppressed for a small course cohort.
- Cross-course reports exclude suppressed and no-evidence courses from aggregate
  totals, report separate counts, and mark rows as suppressed.
- PDF and CSV exports show the suppressed state instead of zeros.
- Boundary tests cover 0, 1, threshold minus one, threshold, and threshold plus
  one learners, plus per-exercise suppression and no-evidence states.

Required retest:

1. Run the analytics suite against a supported PostgreSQL test database.
2. Deploy to dev and production.
3. Run `validate_analytics.py` and confirm all checks pass.
4. Complete the remaining v2.5.3 release-health gates.
