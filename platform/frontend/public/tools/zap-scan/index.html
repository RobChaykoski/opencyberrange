OWASP ZAP scan planner

Build an authorised baseline or full ZAP scan for a practice web app. This page writes the command and a triage checklist. It never sends a request and it does not run ZAP.

Offline planner

Scope

Baseline spider and passive rules. Safe for a normal practice app.

A full scan sends active attacks. It can change or delete data. Use it only on a disposable practice target with a known restore path.

Reports

The planner validates the URL and quotes it for the shell. It does not accept credentials in the URL.

Stop conditions
  • A page starts returning errors or the app loses data.
  • The target is shared with anyone outside the exercise.
  • You cannot restore the target from a snapshot.
  • The scan leaves the agreed host or path scope.

Before you scan

The copy button stays disabled until all three boxes are ticked.

After the scan

  1. Open the report and sort by risk. Read the request and response evidence, not only the alert name.
  2. Reproduce each finding by hand. ZAP reports candidates; a person confirms an issue.
  3. Mark false positives. Shared hosting, a WAF, and a custom login flow all create noise.
  4. Write the impact in the app's own terms: what data, whose account, what action.
  5. Record the fix, the retest, and the residual risk in the lab workbook or DefectDojo.

What ZAP cannot tell you

  • Whether a business rule is wrong when the request is technically valid.
  • Whether one user can reach another user's data if the app hides the link.
  • Whether a finding is exploitable in this deployment's network and identity context.
  • Whether the app is safe. A clean scan is not a security proof.
