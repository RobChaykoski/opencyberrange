# OT01-L2: Modbus Write Single Register — Prompt Questions (Planned)

## Ethical Write Operations
1. Function code 0x06 writes a single holding register. What are the ethical concerns surrounding unauthorized writes to industrial controllers?
2. If a safety-critical setpoint (e.g., maximum motor speed, tank high-level alarm) were modified via a write single register, what immediate physical consequences could result?
3. Under what authorized circumstances might a control system engineer legitimately write to a holding register? What approval workflow should be followed?

## Write Validation
1. How would you validate that a register write was successful? What response does the PLC return?
2. What would happen if you wrote an out-of-range value to a register (e.g., a negative temperature setpoint for a boiler designed for positive values only)?
3. How can you detect unauthorized writes in real-time? What logging or monitoring would you configure?

## Defensive Takeaways
1. Recommend a "write-cooldown" or "confirm-before-write" UI pattern for HMI/SCADA interfaces.
2. Describe how a write-filtering gateway could prevent unauthorized register modifications.
3. If you discovered an unauthorized write in your logs, what incident response steps would you take first?

## Extension: Broadcast Writes
1. Function code 0xFF (or unit ID 0 with 0x05/0x06) can write to all devices on a Modbus segment. What are the risks of accidental or malicious broadcast writes?
2. Under what controlled circumstances might broadcast writes be useful in an industrial setting?
3. How would you segment your network to prevent broadcast write domains from spanning multiple PLCs?
