# Helios Freight - Full Packet Capture Triage

Status: **course**. The live three-run harness passes (build, start, health,
network isolation, two solve passes and resource usage). Instructor review and
difficulty confirmation are still pending.

## Overview

Students receive a short, synthetic full-packet capture that has already been
indexed in Arkime. They use the Arkime viewer to move from a DNS answer to an
outbound HTTP session, reconstruct the exchange and recover the token placed in
the request path. The exercise is about session triage, not packet-level
decoding: the learner must choose the destination, filter the indexed sessions,
read the request metadata and record the evidence.

The capture uses documentation ranges (`10.20.1.0/24`, `198.51.100.0/24`,
`192.0.2.0/24`) and fictional hostnames. No live traffic is captured and no
customer data is present.

## Architecture

```text
learner browser
  -> http://arkime.lab:8005 (basic auth)
  -> Arkime viewer
  -> OpenSearch (internal lab network only)
  -> synthetic PCAP imported once at startup
```

| Service | Image | Exposure |
|---|---|---|
| `arkime` | Arkime 6.9.2 on Debian 13, built from the pinned release .deb | Lab bridge, port 8005 |
| `opensearch` | OpenSearch 2.19.3, single node, security plugin disabled | Internal network only, no student address |

`opensearch` is labelled `ocr_lab_net: "false"`, so the platform does not attach
it to the student bridge. The only route to it is through the Arkime viewer.
Both services run as non-root users. The OpenSearch index is ephemeral: the
marker document in OpenSearch prevents a duplicate import when the Arkime
container restarts, and a fresh lab spawn recreates both services.

## Access

- URL: `http://arkime.lab:8005` (or the Arkime IP shown in the exercise details)
- Username: `analyst`
- Password: the credential in the exercise details

The viewer uses HTTP basic auth inside the isolated lab network. This is not a
production authentication pattern; it is a lab convenience. A production
deployment should put Arkime behind TLS and an identity-aware proxy, or use
OIDC/header auth.

## Walkthrough

1. Open the viewer and set the time range to **All**. The seed capture is short
   and may fall outside the default window.
2. Search for the external destination:

   ```text
   ip.dst == 198.51.100.47
   ```

   The result is the suspicious HTTP session. Open it and inspect the request
   path, host and user agent.
3. The request path contains the token `arkime_s3ss10n_tr1ag3`. The flag is the
   token wrapped in the lab format:

   ```text
   OCR{arkime_s3ss10n_tr1ag3}
   ```

4. Cross-check the DNS answer for `c2.ocrlab.example` and the second POST to
   `/upload`. Record the exact Arkime expression and the destination in the
   analyst finding. Do not copy the payload or the full URI.

The benign `intranet.ocrlab.example` HTTP session and the DNS TXT lookup are
background traffic. They are there to make the destination choice a decision
rather than a single-result search.

## Evidence and assessment

The learner submits:

- the flag;
- a short analyst finding with the destination, the token and confidence;
- the Arkime expression used to find the session.

A flag alone is not completion evidence. The finding must state what was seen,
which session supports it and what was not determined.

## Build and validate

```bash
python3 scripts/validate-lab.py platform/labs/Network/network-2-7-arkime-session-triage
python3 scripts/validate_lab_metadata.py --labs-dir platform/labs
python3 scripts/generate-lab-manifests.py
python3 scripts/lab_harness.py --lab network-2-7-arkime-session-triage --runs 3 --rebuild
```

The Arkime image downloads the pinned release `.deb` and checks its SHA-256
during the build. The base images are pinned by digest. The synthetic capture is
generated by `containers/arkime/seed_pcap.py`; no binary capture is committed.

Resource envelope: about 3 GB RAM (2 GB OpenSearch, 1 GB Arkime) and a small
ephemeral index. The lab is intended for one advanced exercise at a time; cap
concurrency accordingly.

## Troubleshooting

- **Viewer does not load:** wait up to two minutes for OpenSearch and the seed
  import; then check the Arkime container logs.
- **No sessions:** set the time range to All and confirm the search expression.
- **Authentication fails:** use the analyst credential from the exercise
  details; the admin password is internal to the container.
- **OpenSearch is unhealthy:** the internal network has no egress; the image and
  all packages must be present at build time.
