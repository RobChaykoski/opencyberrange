# Migrations

The platform uses Alembic. The current head at the time of writing is
`0067_course_content_rls`; read the live head from the repository, not from this
page.

## Apply migrations

```bash
cd platform
docker compose --env-file .env -f docker-compose.prod.yml exec -T backend \
  alembic upgrade head
```

The production deploy script applies migrations with the migrator role. Do not
run them as the application role.

## Create a migration

1. Change the SQLAlchemy model.
2. Create a revision with a descriptive message.
3. Review every operation; do not accept an autogenerated diff blindly.
4. Test upgrade from the previous head on a disposable database.
5. Test a restore of a pre-migration snapshot.

```bash
cd platform/backend
alembic revision -m "add example column"
```

The repository guard checks:

- a single head;
- no autogenerate call in application code;
- the baseline is coherent.

```bash
python scripts/check-alembic-safety.py
```

## Safety rules

- One head only. Merge or rebase your revision.
- Make migrations idempotent where the platform supports it.
- Backfill in batches; do not lock a large table for a long transaction.
- Add the column nullable, backfill, then enforce `NOT NULL`.
- Create indexes concurrently where PostgreSQL allows it.
- Have a rollback or forward-fix plan.
- A destructive migration requires a restore drill and an explicit approval.
